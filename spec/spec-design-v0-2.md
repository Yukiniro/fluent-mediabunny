# Introduction

This document replaces the broad 0.2 proposal with one complete business capability: extracting images from video for posters, screenshots, and timeline previews. It specifies single-image extraction, explicit-time batches, and evenly spaced batches together. The interfaces below specify the 0.2 implementation; see the [validation report](../docs/thumbnail-validation.md) for execution evidence.

The project aims to simplify Mediabunny's public capabilities beyond Conversion. This batch uses its video-reading primitives. The baseline is fluent-mediabunny 0.1.0 at f1a4b9a and Mediabunny 1.61.6. Public declarations were rechecked on 2026-10-20. No dependency upgrade is part of this design.

## 1. Purpose & Scope

### Included in this batch

- Extract one image at a requested presentation time.
- Extract an ordered batch from an explicit time list.
- Generate evenly spaced requests within an explicit time interval.
- Select the primary video track or a specific video track ID.
- Encode JPEG or PNG with output sizing and JPEG quality control.
- Apply source orientation, flip, and pixel aspect ratio.
- Return actual frame timing, requested timing, dimensions, and MIME information.
- Support cancellation, early iterator exit, bounded wrapper buffering, and automatic resource cleanup.
- Deliver API documentation, synthetic fixtures, lifecycle tests, and browser evidence as one batch.

### Excluded

No public reader/session API, conversion plan API, enhanced probe, embedded artwork extraction, PCM, waveforms, raw frames/packets, spritesheets, contact sheets, animated image formats, image-file inputs, scene detection, automatic best-poster selection, subtitle rendering, overlays, crop rectangles, additional rotation, or timeline editing. No new input containers, codecs, HLS/live input, stream adapters, server support, automatic Workers, file writing, pickers, downloads, uploads, or codec installation.

Keep `media(source)...run()` and existing `probe()` behavior unchanged. Image extraction reads the source directly and does not inherit any conversion builder settings. Existing AVC sequence restrictions remain conversion-only; image extraction must not add a whole-file transcoding preflight.

## 2. Definitions

- Presentation time: when a frame is displayed, independent of packet decode order or frame index.
- Origin: `max(0, input.getFirstTimestamp())`, shared across the input's tracks.
- Requested time: seconds relative to Origin supplied by the caller or generated by interval sampling.
- Source timestamp: the selected frame's original start timestamp in seconds.
- Actual time: Source timestamp minus Origin; it can be negative for a frame overlapping time zero.
- Missing image: valid input and selected video track, but no frame covers the requested time. This is distinct from invalid media or unsupported decoding.
- Owned result: a Blob whose data remains valid after subsequent results, cancellation, or input disposal.

## 3. Requirements, Constraints & Guidelines

- REQ-001: Export only two new runtime entry points, `thumbnail` and `thumbnails`, plus their documented TypeScript types. Do not add corresponding conversion-builder methods or aliases.
- REQ-002: Reuse the existing MediaInput types, finite-file input format allowlist, URL normalization, anonymous CORS GET policy, and no-retry behavior. Caller-owned bytes and URLs must remain stable until termination.
- REQ-003: Use public Mediabunny APIs for demuxing, track selection, decoding, timing, and geometry. Do not implement codecs or a replacement demuxer.
- REQ-004: Validate and snapshot all caller-supplied options and the complete time list before any source read. Do not copy the media bytes. Unknown option keys fail consistently with the existing API.
- REQ-005: A batch opens one Input, selects one track, and reuses one decoding pipeline. It must not repeatedly invoke the standalone API or buffer all encoded images.
- REQ-006: Missing images preserve their request positions. No silent clamping, dropping, reordering, timestamp substitution, or codec fallback.
- REQ-007: Do not require a video encoder to extract a decoded frame; image encoding uses browser Canvas facilities.
- CON-001: No public session, track lock, configurable cache, concurrency setting, or progress callback. For a batch, completed entry count and known total provide progress without a second event API.
- CON-002: Existing conversion safety, defaults, errors, and file-commit behavior remain unchanged.
- SEC-001: Do not copy source metadata into output images or return input URLs in success results. Browser-generated image headers are allowed; this is not a guarantee that visible content contains no private information.

## 4. Interfaces & Data Contracts

### 4.1 Public API shape

The following declarations define the implemented API.

```ts
type ThumbnailImageOptions = {
  track?: "primary" | number;
  width?: number;
  height?: number;
  fit?: "contain" | "cover" | "fill";
  type?: "image/jpeg" | "image/png";
  quality?: number;
  signal?: AbortSignal;
};

type ThumbnailOptions = ThumbnailImageOptions & { time: number };
type ThumbnailsOptions = ThumbnailImageOptions & (
  | { times: readonly number[]; start?: never; end?: never; count?: never }
  | { start: number; end: number; count: number; times?: never }
);

type ThumbnailImage = {
  blob: Blob;
  mimeType: "image/jpeg" | "image/png";
  width: number;
  height: number;
  trackId: number;
  requestedTime: number;
  actualTime: number;
  sourceTimestamp: number;
  durationSeconds: number;
  timeOriginSeconds: number;
};

type ThumbnailItem = {
  index: number;
  requestedTime: number;
  image: ThumbnailImage | null;
};

thumbnail(source: MediaInput, options: ThumbnailOptions): Promise<ThumbnailImage | null>;
thumbnails(source: MediaInput, options: ThumbnailsOptions): AsyncGenerator<ThumbnailItem, void, unknown>;
```

Use `ThumbnailImage`, `ThumbnailItem`, `ThumbnailImageOptions`, `ThumbnailOptions`, and `ThumbnailsOptions` as exported type names. No new runtime class is public.

`thumbnail` returns null for a missing image. `thumbnails` yields one entry per request, including missing entries, until success, failure, cancellation, or caller termination. A successfully completed batch yields exactly the requested count. Index is zero-based. A batch failure stops the batch and rejects the pending or next `next()` call; it does not convert failures into null or continue silently. Earlier yielded results remain valid.

### 4.2 Track selection

Default `track` is `primary`, selected using Mediabunny's primary video track API without a custom preference policy. A numeric value is a nonnegative safe-integer track ID, never an index. Reuse IDs returned by existing `probe()`.

No primary video track or an empty selected video track: NO_TRACKS. A syntactically valid ID that does not identify a video track: INVALID_OPTIONS. Unrecognized codec or failed track decodability query: CODEC_UNAVAILABLE. A decoder that passes capability checks can still fail during execution.

An empty track is not an ordinary out-of-range request. Establish that the selected track contains at least one video packet before treating null frame lookups as missing images. Decoding applies only to the selected video track; other audio/video tracks need no decoder, although metadata reads may be needed to establish the shared Origin.

### 4.3 Time selection and precision

All external times must be finite and nonnegative. Infinity, NaN, negative values, and a negative zero-normalization ambiguity must not enter timeline calculations; treat -0 as 0. Values must remain safely representable at microsecond resolution.

Convert timestamps used for comparison to nearest integer microseconds with `Math.round(seconds * 1_000_000)`. Reject values or origin-plus-time arithmetic outside the safe integer range. This precision rule applies to source frame starts and durations as well as request lookup times. Return requestedTime as the caller's validated seconds (or the generated seconds); return sourceTimestamp/durationSeconds from the selected sample and actualTime as the documented difference. No exact image-byte or sub-microsecond selection guarantee is made.

For request `t`, round `Origin + t` to the documented integer microseconds and pass that value divided by 1_000_000 to the upstream lookup in presentation order. Let S be its rounded source start and D its rounded duration. An image exists only when `S <= requestMicroseconds < S + D`. A null upstream lookup or a lookup outside that coverage returns null. Never hold the last frame indefinitely or jump to the first frame. If a returned sample has nonfinite timing, unsafe arithmetic, or duration that rounds to zero or less, fail UNSUPPORTED_INPUT rather than guessing its coverage. Exact duplicate presentation starts follow the upstream lookup's selection; no frame-index tie-breaking API is introduced.

Consequences:

- A delayed video track returns null before its first covered instant even if audio has started.
- A gap returns null; the previous image is not extended across it.
- The end of a frame's coverage is exclusive. At a contiguous boundary, the next frame is selected.
- Requests at/after the final frame end return null. Audio duration cannot extend the video's last frame.
- A negative-timestamp frame overlapping zero may be returned with negative actualTime.
- Variable-frame-rate and B-frame inputs use actual presentation timestamps, never `time * fps`.

### 4.4 Explicit batches and interval sampling

Explicit `times` must contain 1..1000 entries in nondecreasing order. Validate the entire copied list before I/O. Duplicates are allowed, appear separately, and can reuse immutable encoded bytes internally. Do not sort or deduplicate user requests. Out-of-range times are valid missing-image requests.

Interval mode requires all of start, end, and count, and prohibits times. Require `end > start` both before and after microsecond rounding and integer count in 1..1000. Generate:

`time[i] = start + i * (end - start) / count`, for `i = 0..count-1`.

This samples the starts of count equal-width bins within `[start, end)`. It includes start and excludes end; count=1 selects start. Example: start=2, end=10, count=4 produces `[2, 4, 6, 8]`. Sub-microsecond spacing can map multiple requests to the same frame or rounded timestamp; preserve all entries. The common rounding rule still applies at the media lookup boundary.

No automatic duration lookup, omitted end, fps-based sampling, or implicit whole-file scan. To span an entire file, the application obtains and explicitly supplies an end. Endpoint exclusion avoids requesting the known final boundary as a supposed image.

### 4.5 Sizing, orientation, and image encoding

| Option                             | Contract                                                                                               |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Neither dimension supplied         | Use the selected sample's oriented display dimensions, rounded to nearest positive integer             |
| Width only                         | Preserve display aspect ratio; height = max(1, round(width / aspectRatio))                             |
| Height only                        | Preserve display aspect ratio; width = max(1, round(height * aspectRatio))                             |
| Both dimensions                    | Require explicit fit; output exactly the requested dimensions                                          |
| fit with fewer than two dimensions | INVALID_OPTIONS                                                                                        |
| contain                            | Center the whole image with aspect ratio preserved; pad the remaining box                              |
| cover                              | Preserve aspect ratio, fill the box, and center-crop overflow                                          |
| fill                               | Stretch to the box; aspect ratio may change                                                            |
| Limits                             | Each explicit/resolved dimension is an integer in 1..4096; resolved area must be <= 16,000,000 pixels  |
| Upscaling / odd dimensions         | Allowed; no even-dimension encoder rule                                                                |
| type                               | Default image/jpeg; image/png is the only other accepted value                                         |
| quality                            | JPEG only, finite 0..1 inclusive, default 0.8; explicitly supplying quality for PNG is INVALID_OPTIONS |

Apply source pixel aspect ratio, rotation, and flip before resolving output geometry. Use sample geometry where exposed rather than silently stretching every sample to the first frame's dimensions. Different returned frames can have different result dimensions when one or both output dimensions are inferred. This batch does not certify every changing-resolution bitstream or normalize unsupported decoder behavior; decoding failures remain errors. Do not run the conversion-only AVC sequence scan.

Implementation compatibility clarification: when a decoded sample reports square pixels, retains the track's coded dimensions, and its track provides a non-square pixel ratio, use the track ratio to complete the sample dimensions. This fallback is required by the tested macOS WebKit decoder. If the decoder changes the raster dimensions, preserve its sample geometry: Linux WebKit materializes this 2:1 ratio as an 80x20 square-pixel raster instead of 160x40. Applying the track ratio again would distort it. Native output dimensions may therefore differ across decoder backends while preserving display aspect ratio. An exposed non-square sample ratio takes precedence and is not applied twice. Fixed track metadata cannot distinguish dynamic pixel-ratio changes that the decoder fails to expose, so correct display of those bitstreams is not guaranteed.

For JPEG, composite transparency and contain-padding onto opaque black. For PNG, preserve decoded alpha where available and use transparent contain-padding. There is no custom background option. Source alpha unavailable from the decoder cannot be reconstructed. Do not promise HDR preservation, controlled tone mapping, or identical colors across browser rendering pipelines.

Reject an over-limit resolved size before allocating its output canvas; never silently shrink it. Native decoder frame memory is outside this canvas allocation guard. For PNG/JPEG encoding, verify that the returned Blob is nonempty and its MIME matches the request. Browser format substitution is IMAGE_ENCODING_UNAVAILABLE; a null or failed encoding operation is PROCESSING_FAILED. The result MIME, Blob MIME, and dimensions must agree with the encoded image.

Do not return Canvas, VideoFrame, VideoSample, object URLs, base64, file handles, or downloaded files. Application code controls object URL creation/revocation and saving. Output is an owned Blob; pooling or reuse must never mutate previously returned images.

### 4.6 Invocation, cancellation, and iteration lifecycle

`thumbnail` is an async operation: validation errors reject its Promise. `thumbnails` is a factory: it snapshots and validates options synchronously and throws INVALID_OPTIONS for malformed options. It performs no source I/O or decoder allocation until the first next(). A valid but pre-aborted signal rejects the first next() with ABORTED without reads. For single calls, validate static options before observing a pre-aborted signal. Returning an unstarted iterator is a no-op with no I/O.

Each invocation owns its Input, sinks, samples, canvases, and abort subscription. Independent invocations do not share a hidden global reader or cache. Concurrent invocations are allowed but consume separate resources. The batch iterator is single-consumer; serialized next()/return() calls are the documented usage.

A batch shares one Input and one sink across requests. It encodes one requested output at a time and must not start the next image encode until the consumer asks for another entry. Upstream bounded decoding read-ahead is permitted. Retain at most one wrapper-owned encoded image plus reusable render buffers, excluding objects retained by the consumer. Upstream source caching and browser codec allocations are accounted for separately; no universal constant-total-memory claim is made.

Always dispose resources on success, error, abort, iterator return(), or early for-await break. Manual iterator consumers must await return() when abandoning work; dropping an iterator reference alone is not a supported cleanup mechanism. An abort signal must initiate cleanup even while the generator is suspended after a yield. The next next() then rejects ABORTED; an explicit return() requests normal termination and awaits cleanup.

Cancellation cannot forcibly interrupt every browser codec or Canvas encoding operation. Stop new work, request input/decoder cancellation, and await wrapper-owned in-flight operations and cleanup. Discard a late encoding result if abort won before that result was delivered. No result is delivered after an observed abort. Already delivered images remain valid. Abort after single-call resolution or normal batch completion has no effect. First-observed terminal failure wins; attach later cleanup errors as diagnostics rather than replacing it. If cleanup alone fails during normal completion/return(), surface PROCESSING_FAILED.

Single-call resolution and a batch's final done/return resolution occur after owned cleanup. Each sample must be released before its corresponding Blob is delivered. A consumer's early break is normal termination, not ABORTED. An abort during slow external I/O has no fixed millisecond completion guarantee.

### 4.7 Error mapping

Use the existing MediaError class and first-failure handling. Extraction errors use existing phase preparing or processing; committing never occurs and targetState is absent because there is no writable target. Add only IMAGE_ENCODING_UNAVAILABLE to the existing ErrorCode union.

| Condition                                                                   | Outcome                    |
| --------------------------------------------------------------------------- | -------------------------- |
| Malformed options, bad track ID/type, invalid range/list/dimensions/quality | INVALID_OPTIONS            |
| Unsupported source type/container, invalid decoded timing/geometry          | UNSUPPORTED_INPUT          |
| No primary video track or selected track has no packets                     | NO_TRACKS                  |
| Selected video cannot be decoded / codec unrecognized                       | CODEC_UNAVAILABLE          |
| Missing rendering/encoding API or image MIME substituted                    | IMAGE_ENCODING_UNAVAILABLE |
| Source fetch/read failure                                                   | READ_FAILED                |
| Decoding, rendering, or image-encoding execution failure                    | PROCESSING_FAILED          |
| Image output exceeds the documented size limit                              | OUTPUT_TOO_LARGE           |
| Observed cancellation before completion                                     | ABORTED                    |
| Valid track but no frame covers requested time                              | null image, not an error   |

Static dimension limits fail INVALID_OPTIONS; inferred or source-native size limits fail OUTPUT_TOO_LARGE. Runtime decoder errors must not be mislabeled as unsupported codec simply because a conversion failed. Native causes remain diagnostic data that applications should sanitize before display.

## 5. Acceptance Criteria

All criteria belong to this batch; none is deferred behind an unrelated API release.

| ID     | Given / when                                                                               | Required result                                                                             |
| ------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| AC-001 | A decodable finite video; request a covered time                                           | JPEG/PNG Blob, correct track and timing fields, decoded image size matching result          |
| AC-002 | Explicit sorted list including duplicates and missing times                                | One entry per request in original order, stable index/time, null retained                   |
| AC-003 | Interval 2..10 with count 4; count 1 variant                                               | Requests exactly 2,4,6,8; count 1 exactly 2; end is excluded                                |

| AC-017 | Create but never start a batch; mutate original options/times after creation               | No initial I/O; iterator uses the original validated snapshot                               |
| AC-018 | Selected decoder unsupported but the source can be probed/copied                           | Extraction reports CODEC_UNAVAILABLE; existing probe/copy behavior remains intact           |
| AC-019 | Import packaged functions from a browser consumer                                          | Both APIs and declared result types usable from built package, not only development source  |
| AC-020 | Run existing conversion, metadata and file-safety suites                                   | No behavior/default regression, all required existing checks pass                           |

## 6. Test Automation Strategy

Use Vite+ and existing Playwright Chrome/Firefox/WebKit projects. Create short synthetic, redistributable fixtures with known colors, frame identifiers, timestamps, orientation and track IDs. Add focused fixtures only where existing ones do not cover acceptance criteria. Use independent ffprobe timing and decoded-image assertions; avoid lossy JPEG byte-equality tests across browsers. PNG and JPEG must each have real success cases on the pinned browser environments, with at least one supported video decoder exercised per project. Additional unavailable codecs are recorded separately, not counted as successful extraction.

Unit/lifecycle tests verify static rules, request generation, safe timing arithmetic, error precedence, cleanup counts, bounded wrapper ownership, MIME substitution, and delayed image encoders. Browser tests verify actual decoded content, dimensions, transparency where supported, sparse selection, URL failure/cancellation, and packaged usage. Native codec memory is not fully measurable by JavaScript heap checks; record repeated-run observations without claiming leak freedom.

Do not repeat failed historical CI as current evidence. Implementation delivery must record dependency/browser versions, actual results, justified skips, and the new revision's CI status. Automated WebKit is not Safari/iOS acceptance. An implementation limitation discovered during development requires a documented design adjustment rather than weakening tests silently.

## 7. Rationale & Context

The batch is a complete video-image extraction workflow, not a single-method release and not a broad media toolkit expansion. Single screenshots, timestamp batches, and timeline sampling share the same decoding, rendering, and lifetime contracts, so they ship together.

Two task-oriented functions avoid a mandatory public session lifecycle. They coexist with the fluent conversion API just as standalone probe does. Batch extraction supplies resource reuse where it materially matters. Equal-bin-start sampling is explicit and does not accidentally request the exclusive final boundary. Missing entries keep UI positions stable.

## 8. Dependencies & Implementation Outline

Keep the pinned Mediabunny version and Vite+ stack. No new runtime dependency is planned. Use the existing input normalization/opening and MediaError conventions. Integrate with Scope where possible; do not change its conversion semantics just to accommodate a suspended extraction iterator.

Planned sequence:

1. Normalize and snapshot options; generate a finite request list.
2. Open one Input, identify the selected video track and common Origin, and check its decodability.
3. Use VideoSampleSink getSample/samplesAtTimestamps (or CanvasSink when timing and per-sample geometry remain sufficient). Sorted requests use the upstream sparse-reading facility.
4. Check frame coverage. Render orientation and size using public sample/canvas facilities; encode one owned Blob and verify MIME.
5. Release the current sample, then resolve/yield the result. For missing coverage, yield the indexed null entry.
6. On any termination, close upstream iterators/samples, dispose Input and render resources, and remove abort listeners.

Use one shared internal extraction path for the two public functions. A reusable internal resource scope is permitted; a public Reader, global cache, custom scheduler, or plugin system is not required. CanvasSink alone must not be trusted to enforce end-of-frame coverage or dynamic sample geometry without verification. Source reads and decode work may be needed before the requested time because of keyframe dependencies; no random-access latency guarantee is implied.

Likely implementation touchpoints are exports/types, a focused image-extraction module, reusable input/error helpers, unit and browser tests, synthetic fixture generation, README examples and validation evidence. Existing conversion planning, target commit logic, codec allowlists and dependency versions are outside the change unless a verified shared bug demands correction.

## 9. Usage Examples & Edge Cases

```ts
import { thumbnail, thumbnails } from "fluent-mediabunny";

const poster = await thumbnail(file, { time: 2, width: 640 });

for await (const entry of thumbnails(file, {
  times: [0, 2, 2, 5],
  width: 160,
  type: "image/png",
  signal,
})) {
  if (entry.image) showPreview(entry.index, entry.image.blob);
  else showPlaceholder(entry.index);
}

for await (const entry of thumbnails(file, {
  start: 2,
  end: 10,
  count: 4,
  width: 160,
  height: 90,
  fit: "cover",
  quality: 0.8,
  signal,
})) {
  showTimelineEntry(entry);
  if (previewClosed()) break;
}
```

Examples show application usage; UI helpers are supplied by the caller. The application handles Blob URLs and their revocation. Retaining every yielded Blob intentionally grows application memory. No underlying input snapshot or remote-content lock is promised. Changing decoded frame dimensions alone is not a reason to run conversion preflight; if exposed correctly by the decoder, resolve geometry per sample, otherwise do not claim support for that bitstream/browser combination.

## 10. Delivery Gate & Subsequent Batches

This design supersedes draft-1's public reader, enhanced probe, PCM/waveform, artwork and plan commitments. `plan()` is removed from the near-term roadmap. All requirements and acceptance criteria above must be addressed before describing video image extraction as delivered. Implementation of this batch was authorized by the user on 2026-10-21.

Subsequent batches remain directions, without assigned release numbers or approved API contracts:

| Business capability           | Candidate scope                                                                |
| ----------------------------- | ------------------------------------------------------------------------------ |
| Media information and tags    | Detailed probe, track attributes, embedded artwork, metadata support expansion |
| Audio extraction and analysis | PCM, time ranges, waveform, explicit timing/channel behavior                   |
| Media creation                | Frames/Canvas/audio to files, timestamps, interleaving, backpressure           |
| Conversion expansion          | Needed formats/codecs and per-track controls with compatibility evidence       |

Recording, HLS and server adapters require their own future scope decisions. Do not implicitly include them in any batch above.
